# AGENTS.md — AI Image Playground

Pure client-side AI image-generation workbench (React 19 + Vite 7 + Tailwind CSS 4 + shadcn-style UI + Zustand + IndexedDB). No backend: all API keys live in `localStorage`, generated assets in IndexedDB. This directory is one package of the pnpm monorepo at the repo root (`aiimage-gen`); sibling `packages/*` exist but have no shared code with this one.

## Commands

Run from this directory (playground), not the repo root:

- `pnpm dev` — two-process dev stack (`scripts/dev.mjs`): the Go API from `server/` on `127.0.0.1:8080` (loads `.env.local` through `ENV_FILE` when it exists) plus Vite on `127.0.0.1:5180` with `--mode go`, which proxies `/api` to Go instead of mounting the Hono API. `--mode go` also loads `.env.go`, so the dev build ships the shared-server UI (`VITE_SERVER_MODE=optional`). `pnpm dev:web` runs only Vite (expects `dev:backend` or any server on `:8080`); `pnpm dev:backend` runs only the Go API. A plain `pnpm exec vite` / `pnpm preview` still mounts the Hono API in-process and reads `.env.local`.
- `pnpm build` — **this is the typecheck**: `tsc && vite build`. There is no separate test suite or lint script here.
- `pnpm build:server` — same, with `VITE_SERVER_MODE=optional` (the shared build that offers server login).
- `pnpm build:go` — build the web app (`VITE_SERVER_MODE=optional` by default) and compile `server/` into one binary with `dist/` embedded; output `build/dist/aiimage-playground`. `pnpm start:go` runs it. Both delegate to the `Makefile` (`make build-go`, `make run`, `make test`, `make clean`); `make dev` is the same two-process loop as `pnpm dev`. `cd server && go test -race ./...` (or `make test`) runs the Go suite. The root `Dockerfile` performs the same web + Go build stages for the container image.
- `pnpm preview` — serve the built output (same port 5180, Hono API mounted too).
- `pnpm deploy:cf` — build, then `wrangler deploy` to Cloudflare Workers (static assets + `/api/*` worker). `pnpm deploy:cf:server` is the `VITE_SERVER_MODE=optional` variant. Repo-root equivalent: `pnpm playground:deploy:cf`. Vercel keeps serving the same `dist/` plus the `api/[[...route]].ts` function through `vercel.json`.
- `pnpm vercel:env` — push every variable in `.env.local` into the linked Vercel project (re-running overwrites; targets production by default, pass `preview`/`development` to change). Requires `vercel link` once.
- `pnpm deploy:vercel` — `vercel deploy --prod`; Vercel builds remotely, so the shared build needs `VITE_SERVER_MODE=optional` pushed via `pnpm vercel:env` first. Repo-root equivalents: `pnpm playground:vercel:env` / `pnpm playground:deploy:vercel`.
- Repo-root equivalents: `pnpm playground` / `pnpm playground:build`. Lint (oxlint, config `../.oxlintrc.json`) is run from the repo root via `pnpm lint`.

Verify changes with `pnpm build`; type errors surface there because tsconfig is `strict` and self-contained. This directory is its own git repository and Vercel's build root, so `tsconfig.json` must not `extends` a file outside it (the monorepo's `../tsconfig.base.json` is absent from the deployed checkout) — keep the compiler options inline.

## Architecture

- `src/pages/` — routes wired in `src/app/App.tsx` under one `AppShell` layout: `/` Free Canvas (`FreeCanvasPage`), `/simple` Simple generate (`SimplePage`), `/workflow` Workflow (`WorkflowPage`), `/gallery`, `/settings`. `/canvas` is a legacy path that redirects to `/workflow` so old bookmarks keep working; `/?mode=simple` redirects to `/simple` for the same reason. `/onboarding` is the exception: a standalone first-run setup page outside `AppShell` (no nav, no results dock), reached by a mount-only gate in `App.tsx` when `isSetupRequired()` is true (no image or LLM key stored, and the guide was never finished/skipped). The flag is persisted as `useConfigStore.onboardingDismissed`, so clearing a key later never pulls the user back; Settings → System re-opens the page.
- `src/stores/` — one Zustand store per concern (`useConfigStore` persisted to localStorage via `zustand/persist`; `useQueueStore` for the generation task queue; `useFreeCanvasStore` for the free-canvas cards, the pending inpaint mask, viewport, a session-only undo stack and quick-mode inputs (`simpleImages`, persisted metadata-only), persisted under `universal-playground-free-canvas`; `useWorkflowStore` for the node graph plus its session-only undo stack, persisted under `universal-playground-workflow` (v2: nodes/edges/viewport only); `useLightboxStore` for the shared image-workspace entry; `useCommandPaletteStore` for the palette/shortcuts dialogs and cross-page clear requests; gallery, prompt). AbortControllers for queue tasks are deliberately kept in a plain `Map` outside reactive state — keep that pattern.
- Undo semantics: workflow snapshots strip runtime node fields (`status`, `progress`, `outputImageUrl`, gallery-save fields, `previewUrl`, `compareUrl`, `outputPrompt`) and merge them back from the current nodes, so undoing a drag or prompt edit keeps generated images. Execution writes never enter history; text edits coalesce per node+field for 600 ms; a drag pushes one snapshot on drop. Free-canvas snapshots hold `{cards, editing, dismissedResultNanoids, ingestSeq}` and merge automatically ingested results that arrived after the snapshot (the ingest watermark), so undo never deletes a fresh generation while explicit dock adds/removals remain undoable. An applied single-image edit is one entry: `replaceCardImage` pushes the pre-edit card (including its mask), so undo restores both the old bitmap and the mask. Neither `past` nor `future` is persisted — history is cleared on reload.
- Free-canvas data model: `cards: CanvasCard[]` with at most one `role: "main"`; other cards are `reference` (ordered by `refOrder`, first 4 participate), `result`, or `free` (canvas-only images that never join generation). An explicit main switch (`promoteToMain` / `setMainFromGallery`) demotes the old main to `free`; clearing the main keeps its historical demotion. Result ownership is separate: one card carries `ownsResult` and survives role changes, so result rows/save retries never depend on the current role. Every card carries an optional `width` in world units (role defaults in `cardStyles.ts`); the corner grip calls `resizeCard` and a double-click restores the default. The store's only pending editing state is the inpaint mask (strokes + brush/invert settings); it applies to the current main image and is discarded after confirmation when the main image is switched/cleared or an edit is applied. `maskVersion` invalidates a confirmation whose mask changed while an async switch was loading. A pending mask means strokes **or** `isMaskInverted`; every clear-main/switch/edit check and its copy must use that same condition. Crop, rotate/flip, canvas expansion, annotation, background removal and upscale are not canvas state — they live in the image workspace and are baked into the card bitmap when applied.
- Placement lives only in `cardStyles.ts`: `layoutPositions`/`layoutCards` pack each region (results under the main card, references and free cards in columns to the right) with width-aware wrapping, so resized cards never overlap after "Tidy layout". `spreadResults()` lines every result up in one row at 360px and the viewport frames exactly those cards. After an explicit main switch, the dock/card caller frames both the new main and the demoted free card (`focusCards`) instead of only the target, so the old main does not land under the results dock; gallery "load as main" passes a one-shot `fitAfterMainSwitch` route state consumed by `FreeCanvasViewport` for the same reason. Initial framing in `FreeCanvasViewport` is React StrictMode-safe: mark `didInitialFit` only inside the second animation frame (the first effect run's cleanup cancels the first frame), and narrow (<640px) mounts refit even when `initialFitDone` is already set, otherwise the 720px main card and its menu stay off-screen after a desktop visit.
- Card headers hold one "More actions" menu instead of an icon row: a narrow card cannot fit several 24px buttons next to the badge, and earlier versions let them spill outside the frame. Menu items are labelled rows; opening one closes the previous, and an outside press dismisses it. Widths clamp per role (`CARD_MIN_WIDTH`), so the header never collapses below a usable size.
- Simple generate lives in the free-canvas store because the inputs are canvas assets: `simpleImages` (up to 5, first is the base image; blobs in `canvasAssets`, only id/name/assetKey/order persisted). Its page mounts the same `ResultsDock` the free canvas uses, so generation history has one UI and one data source (`useQueueStore`) — do not add a second results implementation. Simple results open the same image workspace with a Simple-specific editable adapter (`useSimpleEdit`): applying writes an independent `simple-*` asset/copy (base replacement or a new reference), never the hidden canvas result card. Saved results can be reused from the gallery ("Use as Simple input") because the queue is not persisted. The input grid must not treat an empty URL as missing until `isHydrated` is true: a storage timeout sets `restoreError`/`hydrationError`, blocks generation, and offers `retryHydrateAssets()`; "Remove unavailable" only ever deletes `missing` entries, never restoring/errored ones.
- `src/services/` — API layer, no React imports. `providers/dispatcher.ts` is the single provider entry and routes to `imageService.ts` (one OpenAI-compatible path, official `openai` SDK). `llmAssistant.ts` is the separate text/Vision endpoint used for prompt polishing and image-to-prompt. `historyDb.ts` owns IndexedDB (db name `universal-playground-db`, version 2) and `canvasAssetDb.ts` reuses the same connection/store for non-gallery canvas assets. Never open a second database; handle `blocked` / `blocking` / `versionchange` and reset the cached `dbPromise`.
- `src/services/imageTools/` — fully local image operations. `upscale.ts` lazy-loads pica for 2×/4× Lanczos resampling; `backgroundRemoval.ts` owns a dedicated worker running MODNet through transformers.js. The worker self-hosts ONNX Runtime wasm through `onnxruntime-web` `?url` imports and downloads the ~6.6 MB model from Hugging Face once (browser-cached). Keep both imports lazy — the editor must stay responsive while the worker downloads and loads.
- `src/components/` — grouped by feature (`FreeCanvas/` viewport + `MainCard` + `ImageCard` + `cardStyles` + toolbar + command bar + results dock; `Simple/SimpleGeneratePanel` — the `/simple` form; `Workflow/` workflow canvas and its node components; `Preview/ImageLightbox` — the single image workspace mounted once in `AppShell`, hosting `Preview/ImageWorkspace`: a header, a PS-style tool rail (view/crop/margin/annotate/remove background/upscale), a contextual options bar, the canvas, a right inspector (image info, pending changes, caller actions, commit) and a zoom/compare status bar. Viewing and editing share one shell; read-only images keep the same shell minus the tool rail and commit footer. `Shortcuts/KeyboardShortcutsDialog`; `CommandPalette`; `Layout`). `components/ui/` holds the shadcn-style primitives (Radix via the `radix-ui` package, plus `confirm-dialog.tsx` for destructive confirmation); build pages from those, style with the `cn()` helper from `src/utils/cn.ts`. `ResultsDock` takes `variant="simple"` on the simple page to hide canvas-only actions.
- The image workspace is deliberately generic: `LightboxImage.editable` names the apply label(s) and receives `{blob, width, height}`; `applyConfirm` carries caller-localized copy for destinations that replace something (the Simple base), while `discardWarning` keeps the canvas mask confirmation. The workspace never imports canvas/gallery/workflow stores. `useCardEdit` is the canvas-side adapter (`replaceCardImage` in place + optional `addLocalResult` copy); `useSimpleEdit` is the Simple adapter (base replace / reference append / input replace). Any new surface that can show an image opts in by supplying the callback — do not bolt per-image tools back onto a page.
- `src/utils/keyboard.ts` owns canvas keyboard governance: `isEditableTarget` (input/textarea/select/contentEditable/textbox), `isImeComposing`, `isOverlayOpen` and `shouldIgnoreCanvasHotkey`. Radix closes dialogs on the same Esc keydown, so the overlay state is snapshotted in the capture phase — one Esc closes the overlay only, a second Esc clears canvas selection. All canvas hotkeys pass `shouldIgnoreCanvasHotkey` as `ignoreEventWhen`; never re-enable form tags for Delete/Backspace/mod+z.
- `src/hooks/useGenerateAction.ts` is the only parameter-assembly path for generation (`useGenerateAction("canvas" | "simple")`: main export + first 4 references + mask, or simple-mode images in order; model gate; returns the created task ids). The main image is sent as stored: single-image edits are already baked into its bitmap, so there is no pending crop/rotation/annotation to compose and no implicit outpainting prompt. `src/hooks/useResultIngestion.ts` is mounted once in `AppShell` and ingests every done queue result into the canvas, deduped by `result.nanoid` only.
- `src/utils/composeMain.ts` is the single image-composition pipeline: `drawEditorComposite`/`buildEditorCanvas` render the workspace preview and the committed bitmap (rotate/flip, margin, crop, strokes) at one shared scale model, while `composeMaskImage`/`drawMaskOverlay` build and display the inpaint mask. Do not fork another canvas pipeline or draw the same composition twice.
- `src/utils/proxy.ts` — optional CORS proxying; URL format is `https://<proxy-domain>/<target-url>` (tbxark/vercel-proxy convention). `corsProxyMode` in the config store selects `auto` (default: direct first, a host the browser blocks is retried through the proxy and remembered for the session), `always` (rewrite every request) or `off`. Both the OpenAI SDK clients and `fetchAsBlob` must go through `corsAwareFetch`; do not hand-proxy URLs at call sites.
- `src/utils/workflowCodegen.ts` turns the workflow graph into the standalone OpenAI SDK TypeScript script shown by `WorkflowCodeDialog`. It must mirror the runtime payload in `imageService.ts` (including async `task_id` polling), reuse the exported assistant system prompts, and never embed API keys — keys are emitted as environment variables. Update it when the generation payload changes.
- Deployment: one `dist/` feeds both hosts, plus a Hono API in `functions/` with dependency-free contracts in `shared/` (never `src/`-only, so both sides can import it). Cloudflare uses `wrangler.jsonc` (`main: functions/adapters/worker.ts`, Workers Static Assets with `run_worker_first: ["/api/*"]` — mandatory, otherwise the SPA fallback answers `/api/*` with `index.html`) plus `public/_headers`. Vercel uses `vercel.json` (framework vite, immutable asset caching) plus the `api/[[...route]].ts` Node function, which re-exports the esbuild bundle `api/_handler.cjs` built from `functions/vercel.ts` by `scripts/bundle-vercel-api.mjs` inside `buildCommand`. Locally, the vite dev/preview middleware mounts `createApp(loadEnv(...))` for plain `vite`/`vite preview`; `pnpm dev` instead proxies `/api` to the Go server (see Commands).
- `server/` — a second, interchangeable implementation of the same API for a plain VPS/Docker host: Go stdlib only (`net/http`; the HS256 JWT in `token.go` uses `crypto/hmac`), no JS runtime and no third-party module. It serves the SPA from `//go:embed all:web/static` (populated by `build.sh` or the root `Dockerfile`), keeps the client-facing routes and JSON shapes from `functions/` + `shared/contracts.ts`, and adds `HOST`/`PORT`/`ENV_FILE`/`LOG_LEVEL`/`TRUST_PROXY_HEADERS`/`UPSTREAM_PROXY_URL` env vars plus a `-healthcheck` flag. `TRUST_PROXY_HEADERS` defaults to false; only enable it behind a proxy that overwrites `X-Forwarded-For`. `newHandler(cfg, handlerOptions{...})` is shared with the tests, which inject `handlerOptions.staticFS`/`httpClient`.
- **Shared-server feature is isolated by the compile-time flag `VITE_SERVER_MODE`** (`off` default | `optional`), read once in `src/features/serverMode.ts`. `off` keeps the app's behavior identical to the pre-server app (no login UI, no `/api/*` calls) even if localStorage still holds a token from a shared build. Client wiring: `useServerStore` (persisted `token`/`tokenExp` under `universal-playground-server`), `useManagedConfigStore` (`GET /api/config` after login; managed image selection persisted separately under `universal-playground-managed`), `src/services/runtimeConfig.ts` + `src/hooks/useRuntimeImageState.ts` (the single source for pickers and generation gates; local config is never merged or mutated), `src/services/managedBackend.ts` (`POST /api/generate`, `GET /api/tasks/:id`, `POST /api/assistant/chat`; no assistant model and only an allowlisted image model cross the wire), and managed 401s mark the session unauthorized. Managed sessions call typed application endpoints; local sessions keep the OpenAI SDK and local catalog. The server verifies the JWT, serves `MANAGED_IMAGE_MODELS`/`MANAGED_LLM_MODEL`/`MANAGED_VISION_MODEL` via `/api/config`, enforces the image allowlist and fixed assistant models, and injects upstream keys (`LLM_*`/`IMAGE_*`, IMAGE falling back to LLM; `AUTH_USERNAME/AUTH_PASSWORD/JWT_SECRET` enable login). Settings hides the image/assistant sections for managed users; Onboarding only offers local setup before login. Generated-image URL downloads still go direct through `fetchAsBlob`/CORS proxy. `workflowCodegen.ts` export is hidden in managed sessions because it targets a direct upstream key.

Path alias: `@/` → `src/` (vite.config.ts + tsconfig paths).

## Conventions

- **i18n**: all user-facing strings go through `react-i18next`. Add every new key to **both** `src/i18n/locales/en.json` and `zh.json` (docs and code comments are written in English; Chinese copy lives in `zh.json`). Top-level groups are per domain: `freeCanvas.*` (free canvas UI, including `freeCanvas.cards.*`), `simple.*` (quick generate mode), `preview.*` (shared large-image viewer), `workflow.*` (workflow canvas and nodes), `workflowStore.*` (node titles/status toasts), `gallery.*`, `settings.*`, `shell.*`, `palette.*`; the workspace's own copy lives under `preview.workspace.*` (tools, options, inspector) next to the shared `preview.*` viewer keys. Do not pass `count` unless the key defines i18next plural suffixes (`_one`/`_other`); otherwise use explicitly named variables.
- **Styling**: Tailwind CSS 4, CSS-first config — theme tokens are defined in `src/styles/globals.css` via `@theme inline` (shadcn HSL variables); there is no `tailwind.config`. Dark mode is class-based (`@custom-variant dark`), toggled by the theme setting in the config store.
- **States over silence**: visible request/storage states must be explicit (per `.oil-ui/ui-ux/design-note.md`): gallery distinguishes loading / read-error / true-empty / no-match; a failed gallery save must never lose the generated result; do not submit tasks to disabled models; primary actions must stay reachable on narrow screens without hover. Read `../playground/.oil-ui/ui-ux/design-note.md` and `README.md` before UI work.
- Commit style follows the repo root: conventional prefixes (`feat:`, `chore:`).

## Gotchas

- **`config.json` at the playground root contains real API keys** (it is a settings-export file). Never read it, print it, or commit it. The Vite dev/preview server deliberately denies serving it (`fs.deny` in vite.config.ts) — keep that rule when editing the config.
- **Size format is model-dependent**: official DALL·E requires pixel strings (`1024x1024`, `1792x1024`, `1024x1792`); every other OpenAI-compatible model requires aspect-ratio strings (`1:1`, `16:9`, …). Always route through `formatSizeForModel()` in `imageService.ts` instead of formatting inline.
- Concurrency limit (1–4) exists to avoid upstream 429s; task retries and cancellation go through the queue store, not direct calls to the service layer.
- Saved results are not copied into `canvasAssets`: the gallery remains the single authority for them. If gallery LRU trimming removes a record, the canvas card becomes `missing` with an explicit reload/remove state — do not silently substitute a different image.
- Unsaved results DO keep their blob in `canvasAssets` plus `resultMeta`, so "retry save" works after a refresh even though the queue is not persisted. A failed IndexedDB write is marked `persist: "memory"`: the bitmap still works for this session but the card shows an explicit session-only/missing state after reload instead of claiming it was stored. Restored `saveStatus: "saving"` cards are normalized to a retryable failed state because the non-persisted queue cannot still be writing them.
- Asset cleanup is age-graced only. There is no `pagehide` sweep and `pruneCanvasAssets` no longer evicts un-referenced assets inside the grace window: a closing/back-forward-cached page or another tab can still need them. Removed/replaced Simple assets are left for that startup prune instead of being deleted immediately. Consequence: unreferenced assets can live for the grace period (and the count cap no longer forces eviction) — this is deliberate cross-tab safety, not a leak to "fix" with an unload sweep.
- Local tool outputs are `role: "result"`, `origin: "tool"`, `saveStatus: "local"` cards: their blobs live in `canvasAssets`, they show a cyan dot and no gallery retry bar, and they are never saved to the gallery automatically. `addLocalResult` adds one; `replaceCardImage` replaces any card's bitmap in place (one undo step, keeps the pre-edit original for comparison, marks it edited/local, and clears the pending mask when `clearMask` is set). An edited result keeps its generation nanoid, so `syncResultSaveState` ignores it and a later "retry save" writes a **new** gallery record instead of overwriting the original.
- The canvas persists card metadata only: blob/data URLs are stripped, viewport and editing state are not persisted. Hydration resolves `assetKey` → gallery id → remote http → `missing`; edited cards never fall back to the unedited gallery original.
- **Free-canvas image import has three entries**: file pickers, drag-and-drop, and `⌘/Ctrl + V` (a window-level paste listener in `FreeCanvasViewport`). All three call `addFiles`, so role assignment (first image → main, then references) and placement stay identical; one paste batch is one undo step. The paste handler yields to native text paste when focus is editable and the clipboard carries plain text, and it ignores pastes while an overlay is open.
- `Esc` is reserved for closing dialogs/the viewer and clearing selection. It must not navigate: the old AppShell/Settings `escape → /` hotkeys were removed, and any new global Esc handler needs a strong reason. Inside the image workspace, Esc cancels a running background-removal/upscale job first, then leaves compare mode, and only a later Esc closes the workspace — asking first when crop/margin/annotate/remove-background/upscale changes are pending. The workspace's capture-phase handler stops that keydown so Radix never closes the dialog behind the confirm. Compare is only available while no edits are pending: a cropped or expanded frame has a different aspect than the original, so a slider between them would read as two unrelated images.
- **Undo is structural and session-only.** Workflow history deliberately excludes runtime fields, so undoing a deleted node brings back its prompt/config but not its generated image; do not try to snapshot results into history. Neither stack is persisted, and clearing the graph while a generator is still running can drop that result (the execution writes into nodes that no longer exist). Say so in UI copy instead of hiding it.
- The workflow canvas disables @xyflow's built-in selection and Delete (`elementsSelectable={false}`, `deleteKeyCode/selectionKeyCode/multiSelectionKeyCode={null}`); selection lives in the store and the canvas hotkeys do the deleting. Keep node/edge clicks writing `selectedNodeId` / `selectedEdgeId` — don't reintroduce two selection sources.
- **A workflow node can never connect its own output to its own input.** The guard exists in four places and they must stay aligned: `isValidConnection` on the canvas (prevents the drop), `onConnect` (warning toast), `addEdge` in the store (rejects programmatic/import paths), and `importGraph` + `onRehydrateStorage` (drops legacy self-loops). A self-edge has no execution order and would read its own stale value.
- **Command palette button**: `react-hotkeys-hook` matches `event.code`, so a synthesized `KeyboardEvent` never triggers it. Open the palette through `useCommandPaletteStore.togglePalette()`, not by dispatching events.
- Workflow node `title` is materialized via `i18n.t` when the default graph module loads or when a node is added, and is persisted as data. Switching the UI language does not retranslate existing node titles — a known limitation of the stored-title schema, not something to patch by re-seeding titles on language change.
- Simple generate is its own top-level segment (`/simple`, nav label "Simple"), not a mode inside the free canvas: switching segments keeps prompt/params/results because they live in shared stores, and the model gate copy/CTA belongs in `SimpleGeneratePanel`, not in the canvas toolbar.
- **Cloudflare caps one static asset at 25 MiB.** The app ships an ONNX Runtime wasm: keep the standard `ort-wasm-simd-threaded.wasm` (13.6 MiB) and never switch back to the `.asyncify` build (25.6 MiB, WebGPU/proxy-only). `transformers.js` still embeds an asyncify URL, so `vite.config.ts` deletes that emitted asset in `generateBundle`; the surviving runtime reference is behind a `!wasmPaths` guard. After touching these imports, run an actual background removal — a passing build does not prove ORT initializes.
- `public/_headers` is Cloudflare configuration (Vercel serves it as an inert file and keeps using `vercel.json`). `run_worker_first: ["/api/*"]` in `wrangler.jsonc` is mandatory now that the worker exists; without it the SPA fallback answers `GET /api/*` with `index.html` instead of reaching the Worker.
- **Three Vercel quirks are load-bearing for the API function; `vercel dev` reproduces all of them, so verify there before deploying.** (1) With the framework vite preset, `api/[[...route]].ts` only matches single-segment `/api/*` paths on its own — multi-segment ones 404 at the edge. `vercel.json` therefore keeps the SPA rewrite as `/((?!api/).*)` (a plain `/(.*)` also swallows `/api/*`) and adds `{ "source": "/api/(.*)", "destination": "/api/[[...route]]" }` first. (2) @vercel/node emits true ESM for `type: module` projects and cannot resolve imports outside `api/` — the deployed entry imports the self-contained `api/_handler.cjs` (underscore prefix keeps it from being treated as its own function). (3) A pass-through `fetch()` Response loses its body in the Node runtime, so the proxy buffers upstream responses with `arrayBuffer()` before returning a fresh Response. After touching any of this, verify `GET /api/health` AND a multi-segment route (`POST /api/auth/login`) on the deployed URL.
- **The Go server embeds the frontend at compile time.** After any frontend change rerun `pnpm build:go` (or `make build-go`); the binary lands in `build/dist/aiimage-playground`, and `server/web/static` is only the gitignored `go:embed` staging directory. A bare `go build` embeds whatever is in `server/web/static`, which on a clean checkout is only the committed placeholder (the server then answers with a build hint instead of the app). `server/` duplicates the routes, error codes and JSON shapes from `shared/contracts.ts` — change both implementations together. Keep `config.json` and `.env*` out of the Docker build context (see `.dockerignore`). Login throttling ignores `X-Forwarded-For`/`CF-Connecting-IP` unless `TRUST_PROXY_HEADERS=true`; enabling it behind a proxy that appends instead of overwriting reintroduces the spoofing hole.
- **The Go dev proxy must keep the client `Host` header.** In `vite --mode go`, `/api` is proxied with `changeOrigin: false`; the Go server's same-origin guard compares the browser `Origin` with the `Host` it received, so rewriting Host to `:8080` makes every managed request fail with `cross_origin_forbidden`. `scripts/dev.mjs` starts the backend before Vite and stops both together — keep that coupling when editing either side.
- **The Go server's outbound proxy is env-only.** Upstream calls use `UPSTREAM_PROXY_URL` (validated at boot; `http`/`https`/`socks5`/`socks5h`) when set, otherwise the standard `HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY`; loopback targets always dial directly, which also keeps the httptest-based Go suite off a developer's proxy. `-healthcheck` never proxies (a global `HTTP_PROXY` would otherwise swallow the `127.0.0.1` probe). The Hono implementation in `functions/` ignores these variables entirely.
- Server secrets live only in env (`.env.local` locally, `wrangler secret put` / Vercel dashboard in production). `config.json` is unrelated to them and still must never be read or committed. The login JWT is stored in `localStorage` under `universal-playground-server`; treat it like any other credential-bearing storage.
- This directory is its own git repository and a standalone build root, so it keeps a local `pnpm-workspace.yaml` even inside the monorepo: a clean checkout needs `esbuild` and `workerd` build scripts approved, or pnpm 12 fails the install with `ERR_PNPM_IGNORED_BUILDS`. Do not delete it as duplicate config.
- `dist/` and `build/` are local-only build artifacts; don't commit them. `make clean` removes both plus the staged SPA.
